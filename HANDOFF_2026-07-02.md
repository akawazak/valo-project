### Account renewal and cookie persistence

Files:

- `frontend/src/components/AccountManagerModal.tsx`
- `frontend/src/context/DataContext.tsx`
- `frontend/src/app/globals.css`
- `frontend/src-tauri/src/lib.rs`

Implemented:

- Bulk renewal no longer returns immediately when a background refresh owns the global refresh lock. Manual renewal waits and retries against the latest stored account.
- Bulk renewal is sequential and paced to avoid bursting Riot auth endpoints.
- The Account Manager shows:
  - current account being checked;
  - checked/total progress;
  - renewed/not-renewed counts;
  - accurate stopped/remaining counts;
  - per-account last-renewed time and last failure;
  - Renew, Retry, or Repair instead of one ambiguous action.
- Permanent cookie rejection is distinguished from temporary renewal failure.
- Cancel resolves queued renewal waiters and stops the active request.
- Fresh logins now create their final `account_<uuid>` WebView2 user-data folder up front and keep that folder permanently.
- The old temporary-folder copy/swap path was removed. Microsoft documents the WebView2 user-data folder as the persistent cookie store and warns against moving/deleting it while browser processes may still hold it.
- Native cookie capture retries before falling back to the persisted WebView2 cookie database.
- Successful sessions are marked `.claimed`; abandoned login folders are removed at startup, while claimed folders keep cookies and only disposable caches are pruned.
- Replaced/deleted `account_*` sessions are removed only after the updated account list is persisted.
- Startup no longer bursts renewal requests across every expired account. The active account renews near expiry; inactive accounts use the explicit paced bulk action.
- Login no longer performs an unnecessary second token refresh immediately after Riot OAuth succeeds.
- Existing legacy `session_<puuid>` folders remain supported and were not rewritten or deleted.

Not yet proven:

- Confirm a Riot `429` or network failure produces **Retry**, not **Repair**.

Proven on 2026-07-02:

- Bulk renewal completed against the large saved-account set: **35 renewed, 3 not renewed**.
- The bulk button remained available afterward as `Renew Access (3)`.
- Failed raw-cookie renewal fell back to the same saved WebView2 browser session used by per-row Repair.
- Before the re-login batch, all 39 then-persisted accounts had a corresponding legacy session folder; none were missing.
- The currently persisted account has both an SSID cookie and its legacy WebView2 session reference.
- The user re-logged every current account except `akawazak#ttv`. The resulting persisted set has **36 unique accounts**: 35 new permanent `account_*` sessions and the unchanged akawazak legacy session.
- All 36 accounts have OAuth tokens, a saved SSID, unique session references, and existing session folders; all 35 new sessions are marked `.claimed`.
- After restarting the exact workspace app, all 36 accounts and SSIDs remained, all 35 claimed sessions survived, and the two unclaimed/unreferenced login-attempt folders were removed.
- Every new session has a non-empty WebView2 Cookies database and Chromium `Local State`; integrity coverage is **35/35**.
- After 18 access tokens expired, the real Account Manager `Renew Access (18)` flow renewed **18/18** from the saved sessions with **0 not renewed**.
- Persisted-state verification after the run reported 36/36 valid tokens, 36/36 saved SSIDs, 0 expired tokens, 0 refresh errors, 36 unique session references, and no missing folders.
- One newly created Riot account currently has no assigned game name/tag and therefore displays as `Unknown`; the user confirmed this is expected and it must not be treated as an auth failure.
- Frontend build/lint and seven Rust session/cookie tests pass on the current code.
